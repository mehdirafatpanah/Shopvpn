## 📖 معرفی

**Shopvpn** یک بات تلگرام حرفه‌ای برای فروش کانفیگ‌های V2Ray است که به‌صورت کامل با Python و aiogram 3 نوشته شده. این پروژه برای استفاده‌ی واقعی و تجاری طراحی شده: چند روش پرداخت خودکار (کارت‌به‌کارت با تشخیص پیامک بانک، درگاه‌های آنلاین متعدد، کریپتو، موتور درگاه سفارشی بدون کد)، تحویل خودکار روی پنل‌های VPN محبوب، سیستم نمایندگی چندسطحی، یک دستیار پشتیبانی هوش مصنوعی، و سه لایه‌ی مدیریت مستقل — **پنل داخل بات**، **پنل وب (داخل Mini App و مستقل)** و **اپ بومی اندروید** — همه با یک تجربه‌ی کاربری کاملاً فارسی و راست‌چین.

## ✨ امکانات

### خلاصه‌ی سریع

- 🔑 تحویل خودکار (Auto-Provision) روی ۵ پنل VPN + بانک کانفیگ دستی
- 💳 هفت روش پرداخت مختلف، همه خودکار و بدون دخالت ادمین (به‌جز کارت‌به‌کارت دستی)
- 🧠 دستیار پشتیبانی هوش مصنوعی با سه ارائه‌دهنده‌ی قابل انتخاب
- 🔄 تمدید آزاد سرویس (هر مقدار حجم/روز دلخواه) روی هر پنل و با هر روش پرداخت
- 🏢 نمایندگی مستقل + حالت «نمایندگی متصل» داخل خود بات اصلی
- 🖥️ سه لایه‌ی مدیریت مستقل: پنل داخل بات، پنل وب (۵ تم قابل‌انتخاب)، اپ بومی اندروید
- 📲 اپ اندروید با اعلان Push واقعی (FCM) و به‌روزرسانی خودکار بدون نیاز به آپدیت اپ
- 🌍 نقشه‌ی جهانی سرورها با تست آنلاین/آفلاین لحظه‌ای
- 🌐 پشتیبانی از هر دو حالت **Polling** و **Webhook** برای دریافت آپدیت تلگرام
- 🚀 ضداسپم، پایش سلامت پنل‌ها، گزارش روزانه‌ی فروش، گروه گزارش تاپیک‌دار، کش‌بک، سکه و قرعه‌کشی شبانه، هدیه‌ی گروهی و Integration API — [جزئیات](#growth-security)

جزئیات کامل هر بخش را از زیر باز کن 👇

<details>
<summary><strong>🤖 بات اصلی (کلیک کن برای باز شدن)</strong></summary>

- 🔑 بانک کانفیگ اختصاصی و یکتا برای هر کاربر، به‌همراه **تحویل خودکار (Auto-Provision)** از طریق اتصال مستقیم به پنل‌های **PasarGuard**، **Marzban**، **Marzneshin**، **Hiddify**، **3X-UI**، **Alireza X-UI**، **Rebecca**، **S-UI**، **WGDashboard**، **MikroTik** و **IBSng** (ساخت کاربر و اعتبار حجمی به‌صورت آنی روی خود پنل، بدون نیاز به انبار کانفیگ دستی — به‌ویژه برای بات‌های نمایندگی)
- 🔗 **اتصال مستقیم محصولات عادی به یک پنل مشخص (بدون نمایندگی)** — ادمین موقع ساخت محصول می‌تواند آن را به یک پنل VPN وصل کند؛ با هر خرید یک کاربر واقعی همان لحظه روی همان پنل ساخته و تحویل داده می‌شود
- 🔄 **تمدید آزاد سرویس (Free-form Renewal)** — کاربر از داخل «حساب من» هر سرویس فعالش را با هر مقدار دلخواه (گیگابایت/روز، با نرخ واحد قابل‌تنظیم توسط ادمین) تمدید می‌کند؛ روی هر ۵ پنل پشتیبانی‌شده و با هر روش پرداخت کار می‌کند
- 👤 **حساب کاربری یکپارچه («حساب من»)** — همه‌ی سرویس‌های فعال کاربر (خریداری‌شده، هدیه، تست) در یک هاب با صفحه‌ی جزئیات مستقل برای هرکدام (مصرف، انقضا، تمدید، QR) قابل مشاهده است
- 🧪 **کانفیگ تست چندپلنی** — به‌جای یک تنظیم سراسری، هر پلن تست پنل/حجم/مدت/پیشوند نام مخصوص خودش را دارد (چند پلن تست هم‌زمان، هرکدام قابل‌تنظیم جدا)
- 🔢 **خرید چندتایی** — انتخاب تعداد با دکمه‌ی +/- در لحظه‌ی خرید، محاسبه‌ی خودکار جمع کل و تحویل هم‌زمان چند کانفیگ از انبار
- 💱 **نرخ خودکار دلار/تتر به تومان** — دریافت زنده از چند منبع پشتیبان (با کش کوتاه‌مدت و نرخ دستی پشتیبان در صورت قطعی همه‌ی منابع) برای قیمت‌گذاری لحظه‌ای محصولات کریپتویی
- 💰 سیستم کیف پول داخلی با درخواست شارژ، ارسال رسید و تایید ادمین
- 🗂️ مدیریت کامل دسته‌بندی و محصولات (فعال/غیرفعال، قیمت، موجودی)
- 🚫 مسدودسازی کاربر توسط ادمین (بدون تاثیر روی دسترسی خود ادمین‌ها)
- 📡 عضویت اجباری در کانال قبل از استفاده از بات (با حالت fail-open برای جلوگیری از قفل‌شدن کامل بات در صورت تنظیم اشتباه)
- 📊 اطلاعات زنده‌ی اشتراک (حجم مصرفی/باقی‌مانده و تاریخ انقضا) مستقیماً از روی لینک ساب کاربر، مستقل از نوع پنل
- ⏰ دو سیستم یادآوری خودکار و مستقل از هم: **یادآوری نزدیک‌شدن انقضا** و **یادآوری اتمام حجم**، هرکدام همراه با کد تخفیف اختصاصی و محدود به زمان
- ⚠️ هشدار خودکار اتمام موجودی محصول به همه‌ی ادمین‌ها با آستانه‌ی قابل‌تنظیم
- 📱 تحویل کانفیگ به‌صورت متن + QR Code
- 🎫 **سیستم تیکت پشتیبانی** داخل بات (ایجاد تیکت، claim، پاسخ، بستن) به‌همراه یک کانال جدا برای پیام مستقیم/چت زنده با پشتیبانی
- 🎨 دکمه‌های رنگی شیشه‌ای طبق Bot API 9.4 برای تمام دکمه‌های منوی اصلی و پنل مدیریت
- 🧩 **چیدمان و شخصی‌سازی کامل منوی اصلی** — تغییر ترتیب، نمایش/عدم‌نمایش، متن و رنگ هر دکمه از داخل پنل مدیریت
- 🏷️ برندسازی فروشگاه (نام فروشگاه، متن بنر Mini App) از داخل پنل مدیریت
- 🏢 پشتیبانی از بات‌های نمایندگی مستقل (Reseller Bots) با دیتابیس جدا برای هر نماینده و اجرای هم‌زمان چند بات با یک Dispatcher مشترک
- 🌐 **حالت اجرا: Polling یا Webhook** — قابل انتخاب با یک متغیر محیطی؛ در حالت Webhook یک سرور aiohttp مستقل درخواست‌های تلگرام را با اعتبارسنجی Secret Token دریافت می‌کند
- 💾 **ذخیره‌ی پایدار وضعیت مکالمات (FSM Storage روی SQLite)** — وضعیت مکالمات نیمه‌کاره با ری‌استارت/آپدیت/کرش بات از بین نمی‌رود؛ برای هر بات (اصلی/نمایندگی) مستقل
- ⏳ **پیام‌های خودحذف‌شونده (Temp Messages)** — ادمین می‌تواند به هر کاربر پیامی بفرستد که بعد از مدت مشخص خودکار حذف شود؛ همین مکانیزم برای حذف خودکار پیام حاوی شماره کارت هم استفاده می‌شود
- 📣 **ابزارهای مستقل ارسال پست تبلیغاتی به کانال** (`channel_post_tool.py`, `channel_add_button_tool.py`) — ارسال پست از خط فرمان یا افزودن دکمه‌ی دیپ‌لینک زیر یک پست از قبل منتشرشده

<summary><strong>🤝 نمایندگی، تخفیف و کیف پول (کلیک کن برای باز شدن)</strong></summary>

- 🏢 **حالت «نمایندگی متصل» (Linked Reseller)** — علاوه بر بات مستقل نمایندگی، نماینده می‌تواند داخل خودِ بات اصلی و از طریق لینک رفرال خودش فعالیت کند، با کاتالوگ محصول و شماره کارت اختصاصی خودش
- 👥 **سیستم زیرمجموعه‌گیری (Referral) با سه مدل مستقل و قابل فعال/غیرفعال‌سازی جداگانه** — هر کاربر یک لینک دعوت اختصاصی دارد (`https://t.me/BOT?start=ref<user_id>`):
  - **① پورسانت درصدی از خرید** — با تایید اولین خرید هر زیرمجموعه، درصدی از مبلغ پرداختی به کیف پول دعوت‌کننده اضافه می‌شود؛ با سقف قابل‌تنظیم برای تعداد نفرات
  - **② کانفیگ رایگان با تعداد دعوت مشخص** — با رسیدن تعداد کل زیرمجموعه‌ها به یک آستانه، یک محصول از پیش‌تعیین‌شده خودکار ساخته و ارسال می‌شود
  - **③ شارژ ثابت کیف پول به‌ازای هر دعوت** — با ورود هر نفر از لینک دعوت، مبلغی ثابت بلافاصله به کیف پول دعوت‌کننده اضافه می‌شود
- 🏷️ کد تخفیف با درصد یا مبلغ ثابت، سقف تعداد استفاده و فعال/غیرفعال‌سازی
- 🎡 چرخ شانس با درصد احتمال برد، لیست جوایز، زمان انقضای کد جایزه و Cooldown قابل‌تنظیم بین دو چرخش هر کاربر

<details>
<summary><strong>🚀 امکانات رشد، امنیت و مانیتورینگ (کلیک کن برای باز شدن)</strong></summary>

**🔐 امنیت و ضدسوءاستفاده**

- 🛡 **ضداسپم کاربران** (`spam_guard.py`) — محدودیت نرخ پیام و دکمه برای هر کاربر (پیش‌فرض ۳۵ درخواست در ۶۰ ثانیه). بار اول هشدار می‌دهد و درخواست‌های کاربر را یک دقیقه نادیده می‌گیرد؛ در صورت تکرار، کاربر خودکار مسدود می‌شود و به ادمین‌ها اطلاع داده می‌شود. ادمین‌ها مستثنی‌اند و دکمه‌های +/- تعداد خرید شمرده نمی‌شوند. روشن/خاموش، حد مجاز و بازه‌ی زمانی از داخل پنل مدیریت بات (**گزارش و سیستم ← ضداسپم کاربران**) و همچنین پنل وب قابل تنظیم است.
- 🎟 **محدودیت‌های پیشرفته‌ی کد تخفیف** — سقف استفاده‌ی هر کاربر، «فقط برای خرید اول» و مخاطب کد (همه / کاربران عادی / نماینده‌ها) علاوه بر سقف کل، انقضا و محدوده‌ی محصول/دسته. مسیر: **بازاریابی و رشد ← کد تخفیف**.

**📊 عملیات و مانیتورینگ**

- 🩺 **پایش سلامت پنل‌های VPN** (`panel_health.py`) — هر ۵ دقیقه اتصال همه‌ی پنل‌های فعال را بررسی می‌کند؛ بعد از چند شکست پیاپی هشدار قطعی می‌فرستد، در قطعی طولانی هر یک ساعت یادآوری می‌کند و با برگشت پنل پیام بازیابی می‌دهد. روشن/خاموش از پنل وب (تنظیمات).
- 📊 **گزارش روزانه‌ی فروش** (`daily_report.py`) — هر شب در ساعت تنظیم‌شده به وقت تهران (پیش‌فرض ۲۳:۴۵): سفارش تاییدشده، درآمد، میانگین سبد خرید، در انتظار/ردشده، شارژ کیف پول، کانفیگ تست، کاربر جدید و پرفروش‌ترین محصولات. روشن/خاموش و ساعت از پنل وب (تنظیمات).
- 📣 **گروه گزارش تاپیک‌دار** (`report_router.py`) — یک سوپرگروه با حالت Topics؛ بات خودش تاپیک‌های «خرید، سرویس، تست، مالی، خطا، بکاپ، گزارش شبانه و سایر» را می‌سازد و هر گزارش را در تاپیک مربوط به خودش می‌فرستد. بدون گروه یا هنگام خطا، گزارش‌ها مستقیم به ادمین‌ها می‌رسد. آیدی عددی گروه را با اضافه‌کردن `@myidbot` به گروه و ارسال `/getgroupid@myidbot` بگیر. مسیر: **گزارش و سیستم ← گروه گزارش تاپیک‌دار**.
- 🎁 **هدیه‌ی گروهی حجم/زمان** (`bulk_gifts.py`) — ویزارد دکمه‌ای: انتخاب پنل و/یا کاربران هدف، حجم و زمان با دکمه‌های سریع (یا عدد دلخواه)، صفحه‌ی تایید با تعداد سرویس‌های مشمول، صف پایدار که بعد از ری‌استارت ادامه پیدا می‌کند و لیست عملیات‌های اخیر با امکان لغو. سرویس‌های تست شامل هدیه نمی‌شوند. مسیر: **بازاریابی و رشد ← هدیه‌ی گروهی**.
- 🧹 **پاکسازی خودکار سرویس‌های منقضی** (`cleanup_loop.py`) — مهلت حذف جداگانه برای سرویس‌ها و کانفیگ‌های تست (۰ یعنی خاموش)، هشدار قبل از انقضا، غیرفعال‌سازی روی پنل قبل از حذف و حالت dry-run (پیش‌فرض روشن) که فقط نامزدها را گزارش می‌کند. سرویس‌های On-hold، نامحدود و دارای تمدید خودکار هرگز حذف نمی‌شوند. مسیر: **محصولات و کانفیگ ← پاکسازی خودکار منقضی‌ها**.
- 🔌 **Integration API** (`api/`) — API توکنی مستند برای اتصال سیستم‌های دیگر؛ فقط‌خواندنی است مگر توکن scope صریح `orders:write` داشته باشد. توکن شخصی با دستور `/token2` در بات ساخته می‌شود (با صدور توکن جدید، توکن قبلی باطل می‌شود) و مستندات در `/api/index.html` است. نصب و مدیریت از `manage.sh` گزینه‌های ۲۴ تا ۲۶.

**💰 فروش، سرویس و رشد**

- ⏸ **On-hold: شروع انقضا از اولین اتصال** — سرویس تا اولین اتصال کاربر شروع نمی‌شود (پنل‌های PasarGuard، Marzban، Rebecca و 3X-UI).
- 📦 **سقف ظرفیت پنل** — حداکثر تعداد سرویس فعال برای هر پنل و هشدار پرشدن ظرفیت به ادمین‌ها.
- 📍 **تغییر لوکیشن سرویس** — کاربر سرویس فعالش را به پنل دیگری منتقل می‌کند. هر پنل مقصد هزینه‌ی انتقال جدا دارد و سقف تعداد تغییر برای هر کاربر و سهمیه‌ی رایگان قابل‌تنظیم است.
- 💰 **ویرایش گروهی قیمت محصولات** — بر اساس دسته‌بندی یا پنل، به‌صورت درصدی یا مبلغ ثابت، با گردکردن (۱۰۰ / ۱٬۰۰۰ / ۱۰٬۰۰۰ تومان)، تایید نهایی و **بازگردانی (Undo)** هر تغییر. مسیر: **محصولات و کانفیگ ← محصولات ← ویرایش گروهی قیمت**.
- 💸 **کش‌بک تمدید و شارژ کیف پول** — درصدی از مبلغ هر تمدید (فقط از مبلغی که خارج از کیف پول پرداخت شده) و هر شارژ کیف پول بعد از تایید به کیف پول کاربر برمی‌گردد. صفحه‌ی تنظیم آمار مجموع کش‌بک پرداخت‌شده را هم نشان می‌دهد. مسیر: **بازاریابی و رشد ← کش‌بک تمدید و شارژ**.
- 🎁 **گیفت‌کد شارژ کیف پول** — ادمین کد شارژ می‌سازد و کاربر از بخش کیف پول با «استفاده از گیفت‌کد» آن را وارد می‌کند. مسیر: **بازاریابی و رشد ← کد تخفیف ← گیفت‌کدهای شارژ کیف پول**.
- ⏳ **هزینه و انقضای نمایندگی** — هر سطح نمایندگی می‌تواند هزینه‌ی عضویت و مدت اعتبار داشته باشد و انقضا و یادآوری آن خودکار مدیریت می‌شود. مسیر: **نمایندگی‌ها ← هزینه و انقضای نمایندگی**.
- 🪙 **سکه و قرعه‌کشی شبانه** (`lottery_loop.py`) — هر خرید و تمدید تاییدشده و هر زیرمجموعه‌ی جدید (به‌محض عضویت، بدون نیاز به خرید) سکه می‌دهد (مقدار هرکدام قابل‌تنظیم). کاربر از «کیف پول ← 🪙 سکه‌های من» انتخاب می‌کند سکه‌هایش برای قرعه‌کشی باشد یا به موجودی کیف پول تبدیل شود. هر سکه از لحظه‌ی دریافت، و موجودی حاصل از تبدیل سکه از لحظه‌ی تبدیل، مهلت استفاده دارد (پیش‌فرض ۷ روز؛ هر دو از همان صفحه قابل تنظیم‌اند و ۰ یعنی بدون انقضا). ادمین ارزش هر سکه (تومان)، حداقل و حداکثر سکه در هر تبدیل و حداقل سکه برای ورود به قرعه‌کشی را تنظیم می‌کند (۰ برای ارزش سکه یعنی تبدیل غیرفعال). هر شب ساعت ۰۰:۰۰ سه نفر با بیشترین سکه بین شرکت‌کنندگان برنده می‌شوند و سکه‌ی همه‌ی شرکت‌کنندگان صفر می‌شود (سکه‌ی کاربرانی که در حالت تبدیل به کیف پول هستند دست‌نخورده می‌ماند). جایزه می‌تواند شارژ کیف پول یا کد تخفیف (با اعتبار قابل‌تنظیم) باشد؛ شمول نماینده‌ها، مقصد گزارش (ادمین‌ها یا گروه)، جدول ۱۰ نفر برتر، نتایج قبلی و اجرای دستی قرعه‌کشی در همان صفحه هست. مسیر: **بازاریابی و رشد ← سکه و قرعه‌کشی شبانه**.
- 🎫 **دپارتمان‌بندی پشتیبانی و گزارش اختلال** — تیکت‌ها به دپارتمان‌ها تقسیم می‌شوند و هر دپارتمان ادمین‌های مخصوص خودش را دارد. کاربر از صفحه‌ی سرویس با «گزارش اختلال» مستقیم تیکت می‌سازد.

## 🧠 دستیار پشتیبانی هوش مصنوعی

یک لایه‌ی هوشمند که قبل از رسیدن پیام کاربر به ادمین انسانی، سوالات تکراری و قابل‌پاسخ‌گویی خودکار را جواب می‌دهد:

- 🔌 **سه ارائه‌دهنده‌ی قابل‌انتخاب** — Gemini، Groq یا OpenRouter، با کلید API و مدل قابل‌تنظیم از پنل ادمین (بدون نیاز به `.env` یا ری‌استارت سرور)
- 📚 پاسخ به سوالات متداول (نحوه‌ی اتصال، تفاوت پلن‌ها، سیاست بازگشت وجه و ...) که متنشان را خودِ ادمین می‌نویسد
- 🔎 پاسخ به سوالات مربوط به وضعیت واقعیِ خودِ کاربر (سرویس، انقضا، کیف پول، سفارش‌ها) با **function calling** مستقیم از دیتابیس — نه حدس زدن
- 🛒 نمایش کارت خرید واقعی (قیمت زنده، کیف پول، دکمه‌های پرداخت) از داخل مکالمه، بدون این‌که خودش چیزی تغییر دهد
- 🔒 **قانون سخت‌گیرانه:** این ماژول هیچ عملیات نوشتنی/مالی مستقیم (رفاند، تمدید، تغییر دیتابیس، تخفیف، کسر از کیف پول) انجام نمی‌دهد؛ تسویه‌ی نهایی همیشه با تایید خودِ کاربر روی دکمه‌های واقعی انجام می‌شود
- 🙋 ارجاع خودکار به پشتیبانی انسانی (`escalate_to_human`) هر وقت موضوع مالی/شکایت بود یا کاربر صراحتاً خواست
- ⚡ اگر هیچ کلید API تنظیم نشده باشد، بلافاصله و بدون تلاش برای اتصال، مکالمه به پشتیبان انسانی ارجاع داده می‌شود تا کاربر معطل نماند

## 📲 Mini App

<details>
<summary><strong>جزئیات (کلیک کن برای باز شدن)</strong></summary>

پوشه‌ی `miniapp/` شامل یک اپلیکیشن کامل تلگرام (Telegram Mini App) با دو بخش مجزا است: **فروشگاه کاربر** و **پنل مدیریت وب کامل**.

### 🛍️ بخش کاربر
- ⚡ بک‌اند FastAPI با احراز هویت امن (HMAC-SHA256 روی initData) — آیدی کاربر همیشه سمت سرور استخراج می‌شود
- 🎨 طراحی مدرن و روشن (Light Design System) با انیمیشن و فونت Vazirmatn
- 🛒 فروشگاه، سبد خرید چندتایی، کیف پول، چرخ شانس، زیرمجموعه‌گیری و کانفیگ تست در قالب تب‌های اختصاصی
- 🔔 بنر هشدار نزدیک‌شدن انقضا/اتمام حجم در صفحه‌ی اصلی
- 📲 **افزودن خودکار اشتراک به اپ‌های VPN** — انتخاب پلتفرم (iOS/اندروید) و یکی از اپ‌های محبوب، با دکمه‌ی «⬇️ دانلود» و «📲 افزودن» (Deep Link اختصاصی هر اپ)
- 🎫 سیستم تیکت و چت پشتیبانی زنده داخل اپلیکیشن

### 🛠️ پنل مدیریت وب (داخل Mini App)
یک پنل مدیریت کامل و مستقل، موازی با پنل بات، شامل:
- 📊 داشبورد آماری و خروجی اکسل/CSV از سفارش‌ها
- 🗂️ مدیریت دسته‌بندی‌ها، محصولات (شامل پنل‌های PasarGuard/Marzban/Marzneshin/Hiddify/**3X-UI**) و بانک کانفیگ
- 🏢 مدیریت کامل نمایندگان (افزودن، اعتبارسنجی توکن بات، فعال/غیرفعال‌سازی)
- 🏷️ مدیریت کدهای تخفیف، چرخ شانس، زیرمجموعه‌گیری، یادآوری تمدید و اتمام حجم
- 👥 مدیریت کاربران — جزئیات، مسدودسازی، پیام مستقیم، پیام همگانی به کاربران منقضی‌شده
- 💰 جست‌وجوی کیف پول کاربر و اصلاح دستی موجودی
- 🎨 شخصی‌سازی برندینگ، تم رنگی و تصویر هدر فروشگاه
- 🧩 مدیریت چیدمان منوی اصلی بات از همین پنل وب
- 🎫 مدیریت کامل تیکت‌ها و مکالمات پشتیبانی
- 📝 مشاهده‌ی لاگ‌های سیستم و لاگ فعالیت ادمین‌ها
- 🗄️ دریافت بکاپ فوری و بازیابی دیتابیس مستقیماً از پنل وب

برای نصب و اتصال Mini App به دامنه‌ی خودت (با SSL خودکار)، از گزینه‌ی ۱۰ در `manage.sh` استفاده کن.

## 🖥️ پنل مدیریت وب مستقل (`admin_panel`)

<details>
<summary><strong>جزئیات (کلیک کن برای باز شدن)</strong></summary>

علاوه بر پنل مدیریتِ داخل بات و پنل مدیریتِ داخل Mini App، پروژه یک **پنل مدیریت وب کاملاً مستقل و جدا از تلگرام** هم دارد (پوشه‌ی `admin_panel/`) که می‌تواند حتی بدون باز بودن بات هم روی دامنه‌ی اختصاصی خودش بالا بماند:

- 🔐 لاگین با **یوزرنیم/پسورد** (نه از طریق تلگرام) و سیستم نشست (session) امضاشده‌ی مستقل
- 👥 **مدیریت کاربران پنل وب** با نقش و سطح دسترسی جدا از نقش‌های ادمین بات
- 📊 داشبورد کامل آمار فروش، سفارش‌ها، شارژ کیف پول و وضعیت سیستم
- 🎨 **۵ تم بصری کامل و قابل‌انتخاب** — Glass/Aurora، Cyberpunk، Bento، Neo-brutalist و Street Ops — هرکدام روی تمام صفحات پنل پیاده‌سازی شده
- 📱 **نصب به‌صورت PWA** — قابل نصب روی صفحه‌ی اصلی موبایل (اندروید/iOS) با آیکون و مانیفست اختصاصی، حتی برای هر نماینده با `start_url` جدا؛ Service Worker برای پایداری بیشتر
- 🌍 **نقشه‌ی جهانی سرورها** — اسکن خودکار لینک ساب مادر، استخراج و geolocate کردن IP سرورهای پشت هر کانفیگ (vmess/vless/trojan/ss/hysteria2/tuic)، تست سلامت واقعی در سطح پروتکل (شامل ترنسپورت `httpupgrade`) برای تشخیص دقیق‌تر آنلاین/آفلاین، با چند منبع CDN پشتیبان و کش محلی برای نمایش سریع‌تر نقشه
- 💱 نمایش و بروزرسانی دستی/خودکار نرخ ارز مورد استفاده برای قیمت‌گذاری
- ✅ تایید/رد سفارش‌ها، شارژ کیف پول و رسیدهای پرداخت مستقیماً از پنل وب (بدون نیاز به تلگرام)
- 🏢 مدیریت کامل نمایندگان به‌همراه **آنالیز کوهورت (Cohort Analytics)** نمایندگان
- 🎫 مدیریت تیکت‌ها و مکالمات پشتیبانی
- 📢 ارسال پیام همگانی (Broadcast)
- 🗄️ دریافت بکاپ فوری و بازیابی دیتابیس
- 🔔 **اعلان Push در مرورگر (Web Push / VAPID)** — اطلاع‌رسانی سفارش/تیکت/شارژ جدید حتی وقتی تب پنل بسته باشد، با فاصله‌ی زمانی بررسی قابل‌تنظیم از خود پنل
- 📱 **مدیریت اپ اندروید** — ساخت/کپی/لغو توکن دسترسی (PAT) برای اتصال اپ بومی اندروید، مستقیم از تب «اپ موبایل» داخل تنظیمات (جزئیات کامل در بخش [اپ اندروید مدیریت](#android-app))
- 📝 لاگ کامل فعالیت ادمین‌های پنل وب

### راه‌اندازی

**خودکار (پیشنهادی):** گزینه‌ی ۱۳ در `manage.sh` — دامنه، SSL و سرویس سیستم‌دی را خودش می‌سازد.

**دستی:**
```bash
# ساخت اولین حساب owner پنل وب (یوزرنیم/پسورد)
python -m admin_panel.create_admin <username> <password>

# اجرای پنل (پشت یک ریورس‌پروکسی Nginx با SSL قرار بده)
uvicorn admin_panel.server:app --host 127.0.0.1 --port 8002
```

برای فعال‌سازی اعلان‌های Push مرورگر، یک‌بار کلید VAPID بساز (یا از گزینه‌ی ۱۶ منوی `manage.sh` استفاده کن) و خروجی را داخل `.env` قرار بده:
```bash
python -m admin_panel.generate_vapid_keys
```

## 📱 اپ اندروید مدیریت

<details>
<summary><strong>جزئیات (کلیک کن برای باز شدن)</strong></summary>

پروژه یک **API اختصاصی برای اپ بومی اندروید مدیریت** هم دارد که همین پنل وب مستقل ارائه می‌کند (endpointهای `/api/app/*` در `admin_panel/server.py` + `admin_panel/mobile_auth.py` + `fcm_client.py`). خودِ اپ اندروید در ریپوی جداگانه‌ای توسعه داده می‌شود؛ این بخش از بک‌اند فقط زیرساخت لازم برای آن را فراهم می‌کند:

- 🔑 **احراز هویت با توکن دسترسی طولانی‌مدت (PAT)** — نه یوزرنیم/پسورد ذخیره‌شده روی گوشی؛ توکن از تب «📱 اپ موبایل» داخل تنظیمات پنل وب ساخته، کپی و در هر لحظه لغو می‌شود
- 🧩 **Server-Driven UI (SDUI)** — ساختار صفحات، تب‌ها، فیلدها و فرم‌های اپ از یک endpoint (`/api/app/config`) خوانده می‌شود؛ یعنی با اضافه‌شدن قابلیت جدید به پنل وب، اپ اندروید **بدون نیاز به آپدیت یا ری‌بیلد** خودش را با آن هماهنگ می‌کند
- 🔔 **اعلان Push واقعی با Firebase Cloud Messaging (FCM)** — نه صرفاً polling؛ تنظیم کاملاً از پنل وب و per-tenant (هر بات پروژه‌ی فایربیس خودش را جدا وارد می‌کند، بدون نیاز به فایل روی سرور یا ری‌استارت سرویس)
- 📋 مدیریت کامل سفارش‌ها (با رسید)، تیکت‌ها، کاربران (جست‌وجو و صفحه‌بندی کامل)، محصولات، تخفیف‌ها، پنل‌های VPN و ادمین‌های وب — شامل فرم‌های ساخت/ویرایش، نه فقط مشاهده
- 🌍 نقشه‌ی جهانی سرورها به‌صورت WebView (تنها بخشی که به‌جای SDUI مستقیم از پنل وب Embed می‌شود)
- 🎨 طراحی به سبک اپ‌های بانکی با پشتیبانی کامل از حالت روشن/تاریک (قابل تغییر از تنظیمات)
- 🔕 امکان روشن/خاموش کردن اعلان‌ها به‌تفکیک هر بخش (سفارش‌ها، تیکت‌ها، کاربران و ...)

</details>

## 🔌 پنل‌های VPN پشتیبانی‌شده

<details>
<summary><strong>جدول کامل پنل‌ها (کلیک کن برای باز شدن)</strong></summary>

اتصال و **تحویل خودکار (Auto-Provision)** کاربر روی پنل، از طریق یک لایه‌ی provider مستقل (`panel_providers/`) پیاده‌سازی شده:

| نوع پنل | وضعیت | نکته |
|---|---|---|
| PasarGuard | ✅ پشتیبانی کامل | احراز هویت با Bearer token؛ گروه/اینباند کاربر جدید از روی یک کاربر نمونه‌ی از قبل موجود روی پنل کپی می‌شود |
| Marzban | ✅ پشتیبانی کامل | همان روش احراز هویت PasarGuard (لاگین با یوزر/پس روی `/api/admin/token`)؛ تفاوت فقط در نام‌گذاری فیلدهای proxies/inbounds |
| Marzneshin | ✅ پشتیبانی کامل | دسترسی کاربر از طریق «سرویس» (Service) به‌جای proxies/inbounds خام؛ endpoint احراز هویت جمع بسته (`/api/admins/token`) |
| Hiddify | ✅ پشتیبانی کامل | احراز هویت با API Key ثابت (نه لاگین یوزر/پس)؛ هویت کاربر روی پنل یک UUID است |
| 3X-UI | ✅ پشتیبانی کامل | احراز هویت با Bearer API Token، سازگار با نسخه‌های جدید که لاگین برنامه‌نویسی را می‌بندند؛ هر کاربر به یک inbound مشخص روی سرور اضافه می‌شود |
| Alireza X-UI | ✅ پشتیبانی کامل | لاگین با یوزر/پس (کوکی) روی `/xui/API`؛ فقط یک inbound و آدرس Subscription جدا انتخاب می‌شود |
| Rebecca | ✅ پشتیبانی کامل | فورک Marzban؛ احراز هویت با Bearer token و سرویس (service) از روی کاربر نمونه |
| S-UI | ✅ پشتیبانی کامل | احراز هویت با هدر `Token` روی `/apiv2`؛ inbound ها از روی کلاینت نمونه گرفته می‌شود |
| WGDashboard | ✅ پشتیبانی کامل | احراز هویت با API Key؛ به‌جای کاربر نمونه، نام configuration (مثلاً `wg0`) گرفته می‌شود؛ حجم/انقضا با Schedule Job اعمال می‌شود و خروجی متن فایل `.conf` است؛ قطع دسترسی/لینک جدید پشتیبانی نمی‌شود |
| MikroTik (User Manager) | ⚠️ محدود | REST API با یوزر/پس روتر؛ حجم/مدت را profile تعیین می‌کند؛ خروجی نام کاربری/رمز است؛ تمدید و قطع دسترسی پشتیبانی نمی‌شود |
| IBSng | ⚠️ محدود | وب‌اسکرپینگ پنل ادمین؛ حجم/مدت را گروه تعیین می‌کند؛ خروجی نام کاربری/رمز است؛ تمدید و قطع دسترسی پشتیبانی نمی‌شود |
| پنل‌های دیگر | ➕ قابل افزودن | با پیاده‌سازی یک provider جدید طبق اینترفیس `panel_providers/base.py` و رجیستر آن در `panel_providers/__init__.py` |

> 💡 دریافت **اطلاعات زنده‌ی اشتراک** (حجم/انقضا از روی لینک ساب کاربر — `sub_info.py`) کاملاً مستقل از این لایه است و با هر نوع پنلی کار می‌کند، چون مستقیم خروجی ساب را می‌خواند نه API پنل را.

</details>

<a id="auto-install"></a>

## 🚀 نصب خودکار (یک‌خطی، پیشنهادی)

برای نصب کامل بات روی یک سرور تازه (Ubuntu/Debian)، فقط این دستور را در ترمینال سرور اجرا کن:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mehdirafatpanah/Shopvpn/main/manage.sh)
```

<details>
<summary>این اسکریپت دقیقاً چه کار می‌کند؟</summary>

1. ✅ پیش‌نیازهای سیستمی (`git`, `python3`, `pip`, `venv`) را نصب می‌کند
2. ✅ پروژه را از گیت‌هاب کلون می‌کند (یا در صورت وجود، آپدیت می‌کند)
3. ✅ محیط مجازی پایتون را می‌سازد و پکیج‌ها را نصب می‌کند
4. ✅ توکن بات و آیدی عددی ادمین را از تو می‌پرسد و فایل `.env` را می‌سازد
5. ✅ یک سرویس `systemd` می‌سازد تا بات همیشه در حال اجرا بماند و بعد از ری‌استارت سرور هم خودکار بالا بیاید

بعد از پایان نصب می‌توانی با دستورهای زیر وضعیت بات را مدیریت کنی:

```bash
sudo systemctl status v2raybot     # وضعیت بات
sudo journalctl -u v2raybot -f     # مشاهده لاگ زنده
sudo systemctl restart v2raybot    # ری‌استارت
sudo systemctl stop v2raybot       # توقف
```

برای آپدیت بات در آینده، کافیست همان دستور نصب یک‌خطی بالا را دوباره اجرا کنی (idempotent است و اطلاعات `.env` را دست‌نخورده نگه می‌دارد)، یا از [پنل مدیریت متنی (`manage.sh`)](#manage-sh) استفاده کنی.

</details>

<a id="manual-install"></a>

## 🛠 نصب دستی

<details>
<summary><strong>مراحل کامل نصب دستی (کلیک کن برای باز شدن)</strong></summary>

**۱. کلون کردن پروژه**
```bash
git clone https://github.com/mehdirafatpanah/Shopvpn.git
cd Shopvpn
```

**۲. ساخت محیط مجازی و نصب پکیج‌ها**
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**۳. تنظیم فایل `.env`**
```bash
cp .env.example .env
nano .env
```

مقادیر زیر را در فایل `.env` قرار بده:
```env
BOT_TOKEN=توکن_واقعی_بات
OWNER_ID=آیدی_عددی_تو
```

> 🔒 فایل `.env` هرگز نباید وارد گیت‌هاب شود (در `.gitignore` قرار دارد). فقط `.env.example` بدون مقدار واقعی در ریپازیتوری نگه‌داری می‌شود.

**۴. اجرا**
```bash
python main.py
```

اگر همه‌چیز درست باشد، بات بلافاصله روشن می‌شود و آماده‌ی دریافت پیام است. دیتابیس به‌صورت خودکار در همان پوشه ساخته می‌شود (`bot_database.db`)؛ نیازی به نصب هیچ دیتابیس جداگانه‌ای نیست.

**۵. اجرای دائمی (بدون بستن ترمینال)**
```bash
# روش ساده با screen
screen -S v2raybot
python main.py
# سپس Ctrl+A و D برای خروج بدون بستن بات

# یا با nohup
nohup python main.py > bot.log 2>&1 &
```

بهترین روش برای پروداکشن، ساخت یک سرویس `systemd` است (که [نصب خودکار](#auto-install) این کار را خودش انجام می‌دهد).

> 💡 بعد از نصب دستی هم می‌توانی مدیریت روزمره‌ی بات را با [پنل مدیریت متنی (`manage.sh`)](#manage-sh) انجام دهی.

</details>

| متغیر | اجباری؟ | توضیح |
|---|:---:|---|
| `BOT_TOKEN` | ✅ | توکن بات اصلی، از [@BotFather](https://t.me/BotFather) |

| `WEBHOOK_SECRET` | ➖ | توکن مخفی تلگرام برای اطمینان از اصالت درخواست وب‌هوک |

| `API_BASE_URL` | ➖ | آدرس پایه‌ی API مینی‌اپ (برای کال‌بک پرداخت کریپتو)؛ اگر خالی باشد خودکار از روی `MINIAPP_URL` استخراج می‌شود |
| `PLISIO_API_KEY` | ➖ | کلید API [Plisio](https://plisio.net) به‌عنوان فال‌بک سراسری (هر بات کلید اختصاصی خودش را هم از پنل تنظیم می‌کند) |
| `ABANGATEWAY_API_KEY` | ➖ | کلید API [آبان گیت وی](https://abangateway.ir) به‌عنوان فال‌بک سراسری |
| `BLUPAL_API_KEY` | ➖ | کلید API درگاه بلوپال به‌عنوان فال‌بک سراسری |
| `NOAPAY_API_KEY` / `NOAPAY_WEBHOOK_SECRET` | ➖ | کلید API و سکرت وب‌هوک درگاه NoaPay (استارز تلگرام) |
| `GEMINI_API_KEY` / `GROQ_API_KEY` / `OPENROUTER_API_KEY` | ➖ | کلید API دستیار پشتیبانی هوش مصنوعی، بسته به ارائه‌دهنده‌ی انتخابی (قابل تنظیم از پنل هم هست) |
| `AI_SUPPORT_MODEL` | ➖ | نام مدل دستیار هوش مصنوعی (پیش‌فرض `gemini-2.5-flash-lite`) |
| `ADMIN_PANEL_SECRET` | ➖ | کلید امضای نشست (session) پنل مدیریت وب مستقل؛ اگر ست نشود مقدار تصادفی ساخته می‌شود |
| `ADMIN_PANEL_URL` | ➖ | آدرس دامنه‌ی پنل مدیریت وب مستقل (`admin_panel/`) |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | ➖ | کلیدهای اعلان Push مرورگر برای پنل وب مستقل؛ با `python -m admin_panel.generate_vapid_keys` ساخته می‌شوند |
| `VAPID_CLAIM_EMAIL` | ➖ | ایمیل تماس همراه کلید VAPID (پیش‌فرض: `admin@example.com`) |
| `FIREBASE_SERVICE_ACCOUNT_PATH` | ➖ | مسیر فایل JSON سرویس‌اکانت فایربیس برای Push اپ اندروید، به‌عنوان جایگزین سراسری (روش پیشنهادی، تنظیم per-tenant از پنل وب → تنظیمات → اپ موبایل است) |

## 🕵️ قابلیت‌های تکمیلی (مستند نشده در بخش‌های بالا)

<details>
<summary><strong>لیست کامل (کلیک کن برای باز شدن)</strong></summary>

علاوه بر همه‌ی موارد بالا، این قابلیت‌ها هم داخل کد پیاده‌سازی شده‌اند:

**🎁 هدیه و وفاداری**

- 🎁 **هدیه‌ی عضویت** (`signup_gift.py`) — کاربرانی که بعد از تعداد روز مشخص (`signup_gift_delay_days`) از عضویتشان هنوز هیچ خریدی نکرده‌اند، به‌صورت خودکار و دقیقاً یک‌بار مبلغ ثابتی (`signup_gift_amount`) به کیف‌پولشان اضافه می‌شود، همراه با پیام اطلاع‌رسانی.
- 💸 **ریفاند خودکار سرویس** (`service_refund.py`) — محاسبه‌ی مبلغ قابل‌بازگشت بر اساس حجم واقعاً مصرف‌نشده‌ی سرویس، با خواندن مصرف زنده از خود پنل VPN.

**📚 آموزش و تجربه‌ی کاربری**

- 📖 **آموزش اتصال قدم‌به‌قدم به‌تفکیک دستگاه** (`tutorial.py`) — ادمین برای هر نوع دستگاه مراحل اتصال (متن/عکس/ویدیو) تعریف می‌کند؛ به کاربر هم با دکمه‌ی «📚 آموزش اتصال» روی صفحه‌ی سرویس و هم خودکار بلافاصله بعد از خرید موفق نمایش داده می‌شود.
- 🧾 **ویرایش تمام متن‌های ربات از طریق سایت** (`text_scanner.py`) — یک اسکنر مبتنی بر AST که کد پایتون خودِ ربات را می‌خواند و هر متنی که با الگوی `db.get_text(...)` نوشته شده باشد را پیدا می‌کند؛ نتیجه با هر بار بالا آمدن بات خودکار در پنل وب زیر تب «متن‌های ربات» ظاهر می‌شود — یعنی تقریباً هر پیامی که ربات می‌فرستد بدون دست‌زدن به کد، از پنل قابل تغییر است.

**🚦 کنترل، ایمنی و هشدار**

- 🔌 **سوئیچ سراسری خاموش/روشن ربات** (`global_switch.py`) — با `/bot_off`، `/bot_on` و `/bot_status` (یا از پنل مدیریت) کل ربات برای کاربران عادی موقتاً غیرفعال می‌شود؛ ادمین‌ها از این محدودیت معاف‌اند و هر بات (اصلی/نمایندگی) سوئیچ مستقل خودش را دارد.
- 🕵️ **هشدار زیرمجموعه‌گیری فیک** (`referral_fraud_alerts.py`) — بعد از هر دعوت جدید، الگوهای مشکوک (دعوت انبوه، نرخ بی‌خریدی بالای زیرمجموعه‌ها) بررسی و در صورت تشخیص، به ادمین‌ها هشدار داده می‌شود.
- 📶 **هشدار اتصال/عدم‌اتصال کاربر** (`connect_alerts.py`) — چون پنل‌های VPN وضعیت آنلاین/آفلاین لحظه‌ای نمی‌دهند، این ماژول از روی مصرف واقعیِ سرویس تشخیص می‌دهد کاربر وصل شده یا نه، و اگر بعد از مدت مشخصی هنوز وصل نشده باشد، به او هشدار می‌فرستد.
- 📣 **اعلان کانالی اتمام/حذف کانفیگ** (`service_alerts.py`) — رویدادهای اتمام حجم/زمان و حذف کانفیگ می‌توانند علاوه بر پیام به کاربر، به یک کانال تلگرامی مشخص هم اعلان شوند.

**⚙️ ابزارهای فنی/زیرساختی**

- 🧩 **رجیستری خودکار «دکمه‌ها»** (`button_registry.py`) — تب سفارشی‌سازی دکمه‌ها در پنل وب با هر دکمه‌ی جدیدی که به منوی اصلی، پنل مدیریت یا مسیر خرید اضافه شود، خودش را بدون تغییر فرانت‌اند به‌روز نگه می‌دارد.
- 👥 **محدودیت تعداد کاربر همزمان روی یک کانفیگ** (`user_limit.py`, `limitIp`) — برای محصولات متصل به پنل، قیمت پایه شامل یک کاربر است و امکان افزودن کاربر بیشتر با قیمت اضافه وجود دارد (فقط پنل‌هایی که از این قابلیت پشتیبانی کنند).
- 🔑 **تغییر یوزرنیم/پسورد پنل وب از خط فرمان** (`admin_panel/change_admin.py`) — `python -m admin_panel.change_admin <یوزرنیم فعلی> <یوزرنیم جدید> <پسورد جدید>` بدون نیاز به ورود به پنل.
- 🗃️ **نسخه‌بندی فایل‌های استاتیک با Content-hash** (`asset_versioning.py`) — جلوگیری از کش قدیمی مرورگر بعد از هر آپدیت پنل وب/Mini App، به‌همراه هدر no-store برای پاسخ‌های API.
- ✍️ **Escape خودکار کاراکترهای Markdown** (`md_utils.py`) — جلوگیری از خطای پارس تلگرام وقتی ورودی کاربر (یوزرنیم، نام کانفیگ و ...) شامل کاراکترهای خاص مارک‌داون باشد.
- 📱 **Schema مستقل تنظیمات برای اپ موبایل** (`settings_schema.py`) — تعریف داده‌محور فیلدهای تب «تنظیمات و برندینگ» تا اپ اندروید بتواند بدون نیاز به آپدیت، همان فرم پنل وب را بسازد.

**🏢 نمایندگی (این بخش کاملاً جدا از «نمایندگی متصل» مستند‌شده در بالاست)**

- 💼 **نمایندگی کمیسیونی با لینک اختصاصی داخل بات اصلی** (`inline_reseller_link`, بند ۳.۱ اسپک) — یک نوع سوم نمایندگی، جدا از «نمایندگی مستقل» و «نمایندگی متصل با کاتالوگ خودش»: نماینده هیچ کاتالوگ یا شماره‌کارت جداگانه‌ای ندارد، فقط یک لینک اختصاصی (`resref_<id>`) می‌گیرد و روی **هر خرید** (نه فقط اولین خرید) مشتریانی که از آن لینک وارد شده‌اند، درصد کمیسیونی که می‌تواند برای هر نماینده جداگانه تنظیم شود به کیف‌پولش واریز می‌شود؛ صفحه‌ی آمار و مدیریت مجزا در پنل ادمین (`adm_commission_resellers_menu`) دارد.
- 📦 **مدل تامین نمایندگی «محصول آماده»** (`reseller_supply_model = fixed_product`) — به‌جای تامین نماینده با اعتبار حجمی (گیگابایت)، می‌توان لیست مشخصی از محصولات را به او تخصیص داد که مصرفش بر اساس «تعداد» است نه گیگابایت؛ ادمین می‌تواند فهرست محصولات مجاز برای این مدل را هم محدود کند.
- 🧭 **فرم درخواست نمایندگی چندمحوره و قابل‌خاموش‌کردن** (بند ۶ اسپک) — فرم درخواست نمایندگی از چند محور مستقل تشکیل شده (نوع بات: مستقل/لینک‌اختصاصی/بدون‌بات، پنل وب، Mini App، مدل تامین: حجمی/محصول‌آماده) که مالک می‌تواند هرکدام را کلاً از فرم حذف کند، نه فقط اجازه‌ی رد کردنش را به کاربر بدهد.

**⭐ نظرسنجی و تجربه‌ی خرید**

- 🗳 **نظرسنجی رضایت سفارش** (`order_surveys`, جدول مستقل در دیتابیس) — ادمین از لیست سفارش‌های تایید‌شده می‌تواند برای خریدار یک نظرسنجی امتیازدهی (۱ تا ۵ ستاره) ارسال کند؛ نتیجه به‌ازای هر پنل VPN هم قابل ردیابی است (فیلد `panel_server_id`)، یعنی می‌شود کیفیت هر پنل را از زبان مشتری‌های واقعی سنجید.
- 🎁 **تخفیف تمدید کامل زودهنگام** (`early_renewal_discount`) — اگر کاربر سرویسش را چند روز (قابل‌تنظیم) قبل از تاریخ انقضا تمدید کند، درصد تخفیف مشخصی به‌صورت خودکار روی مبلغ تمدید اعمال می‌شود.

**💰 عملیات مالی گروهی**

- ➕➖ **افزایش/کاهش گروهی موجودی کیف‌پول** (`adm_bulk_wallet_credit` / `adm_bulk_wallet_deduct`) — ادمین می‌تواند بر اساس فیلتر (وضعیت سفارش، نوع کاربر عادی/نماینده) گروهی از کاربران را هدف بگیرد، قبل از اعمال یک پیش‌نمایش «موجودی قبل/بعد» ببیند و به همه‌شان همزمان مبلغ اضافه یا کم کند (کاهش می‌تواند موجودی را منفی/بدهکار هم بکند).

**📢 پیام همگانی**

- 🖼 **ارسال تصویر در پیام همگانی + رسید تاییدی برای خود ادمین** (بند ۴۴ و ۴۵ اسپک) — پیام همگانی از عکس هم پشتیبانی می‌کند (آلبوم چندعکسی پشتیبانی نمی‌شود)، و دقیقاً همان پیامی که قرار است برای همه‌ی کاربران ارسال شود، یک نسخه هم برای خودِ ادمین کپی می‌شود تا قبل از تایید نهایی، خروجی واقعی را ببیند.

**🔎 ریزه‌کاری‌های دیگر (فقط داخل کد مستند شده‌اند)**

- کد تخفیف مخصوص «تمدید کامل سرویس»، جدا از تمدید آزاد حجم/زمان
- پورسانت زیرمجموعه‌گیری روی *تمدید* سرویس (نه فقط خرید اول)
- نمایش شماره کارت دقیقِ لحظه‌ی خرید به ادمین هنگام تایید رسید (چون ممکن است شماره کارت تا زمان بررسی عوض شده باشد)
- انقضای خودکار سفارش‌های رهاشده‌ای که کد تخفیف رزرو کرده‌اند ولی رسیدی ارسال نشده (برای آزاد شدن مجدد کد)
- بخش‌بندی هوشمند کاربران برای پیام همگانی هدفمند: کاربران بدون هیچ کانفیگ، کاربران با کانفیگ غیرفعال/منقضی، و کاربران قدیمیِ راکد (خرید تاییدشده داشته‌اند ولی مدتی است خرید جدید نکرده‌اند)


**🛒 خرید و مدیریت سرویس توسط کاربر**

- 🧩 **ساخت کانفیگ شخصی (کانفیگ‌ساز چندمحصولی)** — کاربر حجم را خودش انتخاب می‌کند (و در حالت `user_choice` مدت را هم). هر محصول کانفیگ‌ساز پنل/اینباند، بازه‌ی حجم و مدت، قیمت‌گذاری (فلت یا پله‌ای بر اساس بازه‌ی گیگ) و روش‌های پرداخت مجاز مخصوص خودش را دارد. مدیریت از `adm_ccp_*` در پنل ادمین؛ تنظیم قدیمی سراسری (`custom_config_*`) به‌عنوان محصول پیش‌فرض مهاجرت داده می‌شود.
- 🛠 **مدیریت سرویس از صفحه‌ی «حساب من»** — هر دکمه با تنظیم `svc_show_*` جداگانه قابل خاموش‌کردن است: تمدید خودکار از کیف پول، فعال/غیرفعال‌کردن سرویس، تغییر نام، انتقال سرویس به کاربر دیگر (با گزارش برای ادمین)، افزایش تعداد کاربر همزمان (فقط مابه‌التفاوت)، قطع دسترسی و صدور لینک جدید، حذف سرویس با محاسبه‌ی ریفاند، تاریخچه‌ی رویدادها و صفحه‌ی استعلام با جزئیات هر فیلد.
- ⭐ **امتیازدهی ستاره‌ای به هر سرویس** (`service_ratings`) — جدا از نظرسنجی سفارش؛ امتیاز به پنل VPN همان سرویس هم وصل است.
- 💸 **انتقال موجودی کیف پول بین کاربران** (`/transfer_wallet`، جدول `wallet_transfers`) — قابل خاموش/روشن‌کردن با `wallet_show_transfer` و همراه با اطلاع‌رسانی به ادمین.
- 🧾 **دفتر تراکنش کیف پول** — هر تغییر موجودی با یک تریگر SQL خودکار همراه با موجودی قبل/بعد، نوع و یادداشت ثبت می‌شود.
- 💳 **محدودکردن روش‌های پرداخت** برای هر محصول، هر محصول کانفیگ‌ساز و شارژ کیف پول.
- 📦 **تنظیمات تحویل** — خاموش/روشن‌کردن جداگانه‌ی «لینک ساب» و «کانفیگ‌های تکی»، متن دلخواه بعد از تحویل، تصویر پس‌زمینه‌ی دلخواه برای QR، و سقف تعداد محصول خودکار در هر سفارش (`auto_provision_max_qty`).
- 🔗 **لینک ساب با چند دامنه/IP** برای یک سرور (`xui_sub_base_urls`) — لینک‌های جایگزین همان اشتراک از روی دامنه‌های دیگر ساخته می‌شود.
- 📎 **اشتراک هوشمند** (`/smartsub`, `smart_subscriptions`) — با حداقل دو سرویس فعال، لینک ترکیبی `/sub/smart/<token>` ساخته می‌شود. توجه: در این نسخه endpoint سرو این آدرس در ریپو وجود ندارد و قابلیت نیمه‌کاره است.

**🖥 مدیریت پنل و سرور**

- 🔧 **ابزارهای اختصاصی 3X-UI در بات** — ساخت Inbound جدید (پروتکل، شبکه، TLS)، بکاپ و بازیابی خود پنل، و آمار کامل پنل.
- 🎛 **کاربری هر سرور** — برای هر پنل جداگانه تعیین می‌شود که برای خرید شخصی، کانفیگ تست و نمایندگی استفاده شود یا نه، و کاربر نمونه (قالب) هر پنل قابل تغییر است.

**🗄 بکاپ و عملیات**

- 🗂 **بکاپ کامل** (بات اصلی + دیتابیس همه‌ی نماینده‌ها در یک zip) و **بازیابی کامل** از آن، مناسب انتقال کل سرویس به سرور دیگر.
- 📨 **مقصدهای جانبی بکاپ** — چت دوم تلگرام و سرور دوم با SFTP (پسورد یا کلید)، فاصله‌ی بکاپ خودکار قابل تنظیم (`backup_interval_hours`) و دکمه‌ی تست ارسال.
- 🏭 **بازگشت به حالت کارخانه** (فقط مالک، با تایید دو مرحله‌ای).
- 🧹 **پاکسازی کانفیگ‌های یتیم (F147)** و فایل‌های دیتابیس یتیم نماینده‌ها.
- ⏰ **پیام همگانی زمان‌بندی‌شده** (`scheduled_broadcasts`) — حلقه‌ی ارسال در `bot_manager.py`.
- 🔘 **دکمه‌ی منوی تلگرام** خودکار روی Mini App همان بات تنظیم می‌شود (`_sync_menu_button`).

**📈 آمار، لینک تبلیغاتی و پشتیبانی**

- 📈 **آمار پیشرفته** (`get_advanced_stats`) — روند فروش روزانه/هفتگی/ماهانه، عملکرد و نرخ موفقیت هر درگاه، منابع ورودی/کمپین و نمایندگان، قیف تبدیل، مشتریان بازگشتی و ریزش‌کرده و نقشه‌ی ساعتی فعالیت. به‌علاوه آمار دقیق کاربران، برترین خریداران و آمار کامل یک کاربر.
- 🔗 **دیپ‌لینک‌ساز تبلیغاتی داخل بات** — انواع خرید، محصول خاص، کد تخفیف، کانفیگ تست، گردونه‌ی شانس و پارامتر دلخواه (فقط آمار منبع). ورود با هر دیپ‌لینک کاربر را از عضویت اجباری معاف می‌کند و منبع ورود ثبت می‌شود.
- 🟢 **مسیریابی چت زنده بر اساس حضور ادمین** (`admin_presence`) — پیام کاربر فقط برای ادمین آنلاین می‌رود و مکالمه به او اختصاص می‌ماند؛ اگر کسی آنلاین نباشد برای همه ارسال می‌شود.
- 👥 **کاربران** — فعال/غیرفعال‌کردن همه‌ی کانفیگ‌های یک کاربر با یک دکمه و لیست کامل کانفیگ‌های او.

**🌐 پنل وب**

- 🔐 **دسترسی‌های جداگانه برای ادمین‌های وب** (`WEB_ADMIN_PERMISSIONS`).
- 🔔 **پوش «فاکتور معطل‌مانده»** با مهلت قابل تنظیم برای هر درگاه و امکان خاموش/روشن‌کردن پوش هر روش پرداخت.
- 🖼 **بنرهای Mini App** با آپلود تصویر، مرتب‌سازی پنل‌ها و محصولات، و نمایش وضعیت job های پس‌زمینه.

**🏢 رفرال و نمایندگی**

- 🔀 **رفرال چندمرحله‌ای** — درصد جدا برای سطح ۲ و ۳ (`referral_level2_percent`, `referral_level3_percent`)، حداقل مبلغ خرید برای پاداش، و تعلیق خودکار پاداش در صورت تشخیص تقلب (`referral_fraud_auto_suspend`).
- 💳 **اعتبار پس‌پرداخت نماینده** با سقف قابل تنظیم و لاگ کیف پول نماینده.
- 📉 **تخفیف تعدادی هر سطح نمایندگی** (`reseller_tier_qty_discounts`) و درخواست ارتقای سطح.
- 🌐 **نماینده بدون بات** با پنل وب خودش سرویس می‌سازد (`/api/reseller/self-service`) و لینک ورود پنل وب نماینده از بات قابل صدور است.

**🔎 ریزه‌کاری‌ها**

- درگاه سفارشی می‌تواند شماره‌ی موبایل مشتری را با دکمه‌ی اشتراک‌گذاری بگیرد (`require_customer_phone`).
- استارز تلگرام نرخ خودکار به دلار و درصد حاشیه‌ی سود دارد (`tgstars_usd_per_star`, `tgstars_margin_percent`).
- منوی `manage.sh` دوزبانه است (انگلیسی/فارسی با کلید `L`) و انتخاب زبان ذخیره می‌شود.

## پشتیبانی چندزبانه (fa / en / ru / zh / ...)

The project now includes a shared multilingual foundation:
- per-user language is persisted in SQLite (`users.language_code`)
- first `/start` follows Telegram's language, falling back to English (`en`) as the default when the user's Telegram language isn't Persian
- `/language` and the main-menu language button switch between the languages enabled for the bot
- Telegram update middleware applies the selected language safely per request
- bot text overrides continue to work without data loss; translated catalog entries are used where available
- the web admin panel includes a language toggle and switches document direction (RTL/LTR) automatically
- admins can enable additional languages (Russian, Chinese, and other filtering-heavy-region languages such as Vietnamese, Urdu, Kazakh, Uzbek, Turkmen and Belarusian) from the admin panel's language manager; the bot auto-generates the translations on activation
