🔌 درگاه‌های پرداخت سفارشی

هر درگاهی که یک HTTP API داشته باشد را همین‌جا، بدون نوشتن کد، وصل کن. از پلیس‌هولدرهایی مثل {amount}, {order_id}, {callback_url}, {webhook_url} و هر فیلد اعتبارنامه (مثلاً {api_key}) داخل URL/هدر/بدنه استفاده کن.

📖 راهنمای افزودن درگاه جدید (این رو با عکس مستندات API درگاه به هوش‌مصنوعی بده)

این متن رو همراه با عکس/متن مستندات API درگاه پرداخت موردنظر به یه چت‌بات (مثل Claude یا ChatGPT) بده و بگو: «طبق این راهنما فرم رو برام پر کن». پلیس‌هولدرهای قابل استفاده تو URL / هدر / بدنه‌ی درخواست:

  • {amount} — مبلغ نهایی ارسالی (بر اساس واحد/ضریب تنظیم‌شده در بخش «مبلغ ارسالی به درگاه» — تومان/ریال/دلار)
  • {amount_toman} — همیشه مبلغ خامِ واقعی سفارش به تومان، بدون ضریب/تبدیل
  • {currency} — کد ارز مبلغ ارسالی (IRT/IRR/USD)
  • {order_id} — شناسه‌ی داخلی سفارش
  • {description} — توضیح سفارش
  • {callback_url} — آدرس بازگشت مرورگر کاربر بعد از پرداخت
  • {webhook_url} — آدرسی که خودِ سرور درگاه باید بهش وب‌هوک بزنه
  • {تنظیم اعتبارنامه} مثل {api_key} — هر فیلدی که تو بخش اعتبارنامه تعریف کردی
  • {query.X} — فقط تو Verify: پارامتر X از query صفحه‌ی بازگشت
  • {gateway_ref} — فقط تو Verify: شناسه‌ای که خودِ درگاه موقع ساخت فاکتور برگردونده

ساخت فاکتور (اجباری): URL و بدنه‌ی درخواستی که فاکتور می‌سازه، به‌علاوه این‌که تو پاسخ JSON درگاه، «لینک پرداخت» و «شناسه‌ی تراکنش» تو کدوم مسیر هستن (مثلاً data.link یا data.id).

استعلام (Verify) (اختیاری): برای درگاه‌هایی که فقط کاربر رو برمی‌گردونن و باید جدا وضعیت پرداخت رو بپرسیم. از {gateway_ref} یا {query.X} استفاده کن.

وب‌هوک: مهم‌ترین بخش برای تکمیل خودکار سفارش — آدرسش رو (که خودمون به‌صورت {webhook_url} به درگاه می‌دیم) توی بدنه‌ی درخواست ساخت فاکتور به درگاه پاس بده، و بگو تو JSON که درگاه بهش می‌فرسته، «شناسه‌ی تراکنش» و «وضعیت» کجاست.

بعد از پر کردن فرم: «ذخیره» بزن، بعد از دکمه‌ی «تست اتصال» استفاده کن. اگه خطا داد، متن خطا (که معمولاً پیام خودِ درگاهه) رو کپی کن و به همون چت‌بات بده.

💰 مبلغ ارسالی به درگاه

اگه «دلار» رو انتخاب کنی، مبلغ تومانیِ سفارش با نرخ دلار (تنظیمات → کریپتو → نرخ دلار به تومان، یا نرخ خودکار) به دلار تبدیل و همون (بعد از اعمال ضریب) ارسال می‌شه؛ برای تومان/ریال هم ضریب روی همون مبلغ (بعد از تبدیل ریال) اعمال می‌شه. مبلغ تومانیِ واقعیِ سفارش هميشه بدون تغییر و جدا از این تنظیمات هم در {amount_toman} در دسترسه.

مسیر یعنی محل فیلد داخل JSON پاسخ، مثلاً برای {"data":{"id":"x"}} بنویس data.id

اگه فعال کنی، قبل از ساخت فاکتور از مشتری خواسته می‌شه با دکمه‌ی تلگرامی «اشتراک‌گذاری شماره موبایل» شماره‌اش رو بفرسته. دو پلیس‌هولدر همیشه در دسترس‌اند: {customer_phone} (فقط با فعال بودن این گزینه پر می‌شه، وگرنه خالیه) و {customer_user_id} (آیدی عددی تلگرام مشتری، خودکار و بدون نیاز به این گزینه) — می‌تونی توی URL/Headers/Body همین بخش ازشون استفاده کنی.

✅ استعلام پرداخت (Verify) — برای درگاه‌هایی که کاربر را برمی‌گردانند

اگه «مسیر مبلغ» رو پر کنی، مبلغ برگشتی از درگاه با مبلغ واقعی فاکتور مقایسه می‌شه تا با پرداخت کمتر، سفارش تایید نشه.

📡 وب‌هوک (Webhook) — برای درگاه‌هایی که سرور به سرور خبر می‌دهند

⚠️ بدون احراز هویت وب‌هوک، حتماً «مسیر مبلغ در بدنه» رو پر کن؛ وگرنه هرکی txn رو حدس بزنه می‌تونه سفارش خودش رو جعلاً پرداخت‌شده اعلام کنه.
